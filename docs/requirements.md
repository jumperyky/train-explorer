# プロジェクト概要：電車を詳しく学びたい5歳児向けの本格鉄道アプリ「でんしゃ・えき 探検隊」

## 1. アプリの目的とターゲット
- **ターゲット**: 電車や新幹線の細かい情報（停車駅、車両の形、名前など）まで深く知りたい・学びたい5歳の子ども。
- **目的**: 単なるおもちゃではなく、実在する鉄道の正確な情報をベースに、ひらがなや漢字の読み方も学びながら「本物の鉄道知識」を探求できるアプリを開発する。
- **UI/UX方針**: 
  - 全ての漢字にふりがな（ルビ）を振る。
  - 操作は直感的で、ボタンや画像は大きく、誤タップを防ぐレイアウト。
  - 視覚的に楽しいアニメーションやカラフルな配色を取り入れる。

## 2. スコープ（MVP：最小構成）
最初はデータ量とロジックを絞って検証するため、対象を以下の3つのネットワークに限定して実装する。将来的に全国の路線・車両へ容易に拡張できるモジュール設計とする。

- **対象路線・エリア**:
  1. **JR西日本 在来線**: 琵琶湖線・JR京都線・JR神戸線（「新快速」「快速」「普通」による停車駅の違いを実装）。
  2. **東海道新幹線**: 東京 〜 新大阪（「のぞみ」「ひかり」「こだま」による停車駅の違いを実装）。
  3. **近江鉄道（ローカル線）**: 本線・多賀線・八日市線（地域密着の細かい駅網と、独自のローカル車両を表示）。

## 3. 技術スタック・インフラ
- **フロントエンド**: Next.js (React), TypeScript, Tailwind CSS
  - 地図描画: React Leaflet または Mapbox GL JS
  - 音声認識: Web Speech API
- **バックエンド**: Python, FastAPI
  - ふりがな生成: pykakasi または MeCab（動的テキストのルビ振り用）
- **外部API**:
  - 鉄道データ: 公共交通オープンデータセンター (ODPT) API
  - 画像データ: Wikimedia Commons API / Wikipedia API
- **インフラ・デプロイ (Vercel想定)**:
  - フロントエンドはVercelへのデプロイを前提とする。
  - バックエンド（FastAPI）もVercelのServerless Functionsとして統合するか、Render等の別サービスにデプロイするか、構築・運用が一番手軽な構成を提案・実装すること。

## 4. 主要機能要件

### 機能A: 電車・新幹線ずかん（網羅的表示）
- **概要**: 対象の電車や新幹線を一覧表示する機能。
- **詳細**:
  - 「しんかんせん」「JRにしにほん」「おうみてつどう」のカテゴリー分け。
  - 車両の画像（Wikimedia API等から取得）を大きく表示し、正式名称（漢字）とふりがなを併記。
  - タップすると、その車両の最高速度や特徴など「でんしゃのひみつ」が見られる詳細モーダルを表示。

### 機能B: 路線・駅名ガイド（種別ごとの停車駅表示）
- **概要**: 路線ごとの駅一覧と、列車の種別による停車駅の違いを視覚的に表示する別ページ。
- **詳細**:
  - **JR西日本**: 琵琶湖線・JR京都線を選んだ場合、画面上部のボタンで「ふつう」「しんかいそく」などを切り替え。
  - **新幹線**: 東海道新幹線を選んだ場合、「のぞみ」「ひかり」「こだま」を切り替え。
  - **近江鉄道**: 各路線の全駅を表示。
  - 種別切り替え時、止まらない駅は半透明（グレーアウト）になるか、通過アニメーションを表示。
  - 駅名には全てふりがなを振り、現在の駅の「前の駅」「次の駅」がわかる駅名標デザインを採用。

### 機能C: わくわく鉄道マップ（リアル日本地図連動）
- **概要**: 実際の地図の上に、対象駅の場所をピン（スポット）で表示する機能。
- **詳細**:
  - 地図のズームレベルに応じて、最初は新幹線の主要駅のみ、ズームするとJRの駅、さらにズームすると近江鉄道の細かい駅が出現。
  - 駅のピンをタップすると、その駅の「駅名標（ふりがな付き）」と「その駅を通る電車の画像」がポップアップ表示される。

### 機能D: 車掌さんマイク（音声入力検索）
- **概要**: Web Speech APIを活用し、音声で車両や駅を検索できる機能。
- **詳細**:
  - 車掌さんが使うマイクのようなデザインの大きなボタンを配置。
  - マイクボタンを押して「のぞみ！」「おうみてつどう！」と話しかけると、音声認識（文字起こし）を行い、合致する「ずかん」の詳細や「マップ」の該当箇所へ自動でジャンプする。

### 機能E: 外部詳細ページへのセーフリンク（将来拡張用）
- **概要**: 車両や駅のより詳細な情報（Wikipediaや鉄道会社の公式ページなど）を表示する機能だが、子どもが安全に閲覧できるようにアクセス範囲を制限する。
- **要件（Phase 1: 今回の実装範囲）**:
  - 「ずかん」や「マップ」に詳細ページを開くボタンのみ準備。タップしてもアプリ内のモーダルで簡単なテキストが表示されるモック状態とする。
- **要件（Phase 2: 将来拡張）**:
  - ホワイトリスト化された特定URLのみをiframeやバックエンド経由で安全に表示する仕組みを構築予定。

### 機能F: PWA（Progressive Web App）対応
- **概要**: ブラウザから子どものタブレット（Android/iPad等）のホーム画面にアイコンを追加し、ネイティブアプリのようにフルスクリーンで動かせるようにする。
- **詳細**:
  - `manifest.json` を適切に設定し、アプリアイコン、テーマカラー、表示モード（`display: "standalone"` または `fullscreen"`）を定義する。
  - ブラウザのURLバーや戻るボタンなどのUIを隠し、誤操作を防ぐ。
  - Service Workerを導入し、将来的なオフライン動作やキャッシュ機能の土台を作る（MVP段階では基本的なキャッシュのみで可）。

## 5. データ連携とバックエンド要件 (Python/FastAPI)
- **ODPT APIのラップ**: フロントエンドから直接ODPTを叩かず、Pythonバックエンドでデータ取得・整形・キャッシュしてNext.jsに返す設計にする。
- **ルビ振りエンジンの実装**: ODPTのデータ等に対して、Python側で `pykakasi` 等を用いて `<ruby>漢字<rt>かんじ</rt></ruby>` 形式に変換するエンドポイントを用意する。
- **画像取得プロキシ**: 車両名や駅名をキーにして、Wikipedia/Wikimedia APIから代表画像のURLを取得し、フロントエンドに提供する。

## 6. AIへの実装指示ステップ
1. **環境構築とVercel連携方針の提示**: Next.js (app router) と Python (FastAPI/venv環境) の初期セットアップを行い、Vercelにデプロイするためのディレクトリ構成と設定方針（`next.config.js` や `vercel.json` など）を提示してください。
2. **モックデータの作成**: まずはODPT連携前に、JR西日本（新快速/普通）、東海道新幹線（のぞみ/こだま）、近江鉄道の停車駅情報と車両情報が入ったJSONモックデータを作成してください。
3. **PWA設定とUIコンポーネント実装**: `next-pwa`等を用いたPWAの初期設定を行い、5歳児向けの `RubyText` コンポーネント（漢字に自動でルビを振るUI）、大きなボタンのナビゲーション、「車掌さんマイク」ボタンを実装してください。
4. **ページ実装**: 「ずかんページ」「路線ガイド（停車駅切り替え）」「地図ページ」の順にフロントエンドを構築してください。
5. **デプロイ準備**: ローカルでモック動作が確認できたら、VercelにデプロイしてタブレットからPWAとしてインストールできる状態にするための手順を案内してください。
